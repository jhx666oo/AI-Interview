# 宽表管理页自适应布局设计

日期：2026-08-11  
状态：待评审

## 1. 背景与目标

当前系统的主要小屏问题集中在管理类宽表：需求管理、岗位管理、岗位映射、面试官管理、用户管理、入职/试用期管理、面试管理、人才库、工作流、JD 管理、邮件记录、能力维度等页面。表格列较多，页面在 13–16 寸笔记本或浏览器缩放后只能通过底部横向滚动条查看右侧字段，操作按钮也容易离开首屏。

本次改造目标：

1. 大屏保持现有完整表格和字段顺序，不改变业务习惯。
2. 中小屏自动切换为“核心信息卡片 + 展开详情”，首次进入即可看到候选人/岗位主信息和常用操作。
3. 所有字段仍可查看，所有原有操作、批量选择、分页、权限和 API 行为保持不变。
4. 仪表盘上方 KPI、事业部卡片、招聘漏斗和招聘日报/简历管理主列表保持当前样式。
5. 仪表盘底部“全量岗位明细汇总”纳入自适应处理，并保留事业部展开/收起和合计行。

## 2. 当前代码事实

- `AppLayout` 在视口小于 1200px 时自动收窄侧边栏，小于 768px 时切换为抽屉导航。
- `TableViewport` 当前只是 `overflow-x: auto` 的包装器，无法帮助用户发现或避免横向拖动。
- 多数管理页通过 Ant Design `Table` 的 `scroll.x` 固定宽度承载 8–15 列。
- `Dashboard/components/PositionSummaryTable.tsx` 有约 14 列、左侧事业部/岗位列和右侧状态列，并通过 `expanded` 状态控制事业部展开/收起。
- `DailyReports` 和 `Resumes` 主列表已经以卡片/详情为主，不纳入本次重排。

## 4. 方案选择

### 方案 A：仅隐藏低优先级列

改动最小，但用户无法判断哪些字段被隐藏；批量操作和字段查找仍需要额外交互，不能彻底解决信息可见性问题。

### 方案 B：每个页面单独实现移动卡片

视觉可控，但多个页面会重复维护卡片结构、操作按钮和字段渲染，后续容易产生交互差异。

### 方案 C：统一自适应数据视图（采用）

提供一个统一的 `ResponsiveDataView`，桌面端复用 Ant Design `Table`，中小屏复用同一份 `dataSource` 和列渲染函数生成卡片。每个页面只声明主字段、次要字段和操作优先级，不重复实现数据请求或业务回调。

采用原因：同时满足“大屏不改变”和“笔记本首次可见、无需横拉”，并能覆盖当前所有宽表页。

## 5. 交互与布局设计

### 5.1 模式判断

组件使用 `ResizeObserver` 读取自身内容区实际宽度，而不是只读取浏览器视口宽度。这样可以自动适配侧边栏展开/收起、浏览器缩放和不同显示器。

- `full`：内容区宽度 `>= 1180px`，显示完整表格。
- `compact`：内容区宽度 `760–1179px`，显示两列信息卡片；字段详情默认收起。
- `narrow`：内容区宽度 `< 760px`，显示单列卡片；操作按钮换行并保持可点击尺寸。

断点是组件内部的默认值；后续若发现某页面字段密度不同，可通过页面配置覆盖，但不允许恢复 body 级横向滚动。

### 5.2 管理页卡片结构

每条记录的卡片分为四个区域：

1. **身份区**：复选框、主名称（岗位/候选人/用户）、部门或岗位摘要。
2. **状态区**：状态、紧急程度、AI 结果、日期等高频判断字段。
3. **操作区**：保留该行最常用的编辑、发布、同步、入库、删除等按钮；低频操作进入“更多”菜单。
4. **详情区**：通过“展开详情”展示该记录的全部剩余字段，使用两列标签-值布局；窄屏自动变为单列。

长文本使用两行省略和 Tooltip/详情展开，不允许撑破卡片。空值统一显示 `—`，与现有表格保持一致。

### 5.3 字段优先级

每个页面为列声明以下展示级别：

- `primary`：卡片第一行必须显示，例如岗位名称、候选人、用户姓名。
- `secondary`：卡片首屏显示，例如部门、城市、状态、AI 评分、面试时间。
- `detail`：只在展开详情显示，例如预算、备注、Open ID、流程明细。
- `action`：操作按钮，不作为普通字段重复展示。

桌面端仍按原列配置渲染，不改变列顺序；卡片端复用原 `render` 函数，避免状态标签和格式化逻辑分叉。

### 5.4 批量操作与分页

- 复用现有 `rowSelection` 的选中状态和 `onChange` 回调。
- 卡片列表顶部继续提供“全选当前页”；选中后现有批量删除/发布/状态变更按钮保持原位置逻辑。
- 复用现有分页和当前页数据切片，不增加重复请求。
- 展开/收起只影响当前卡片，不改变分页、筛选或选中状态。

### 5.5 仪表盘底部明细表

`PositionSummaryTable` 单独提供卡片渲染器：

- 事业部行继续显示展开/收起按钮、岗位数和汇总指标。
- 展开后岗位行首屏显示岗位、HRBP、优先级、在招人数、简历、通过率、Offer、入职。
- 二面/三面、备注、状态等字段在详情区展示。
- 合计行在卡片列表底部固定显示为“总计卡片”，数据仍来自现有 `totals`。
- `aria-expanded`、键盘操作和现有 `expanded` 状态逻辑保持不变。

## 6. 组件边界与数据流

新增/扩展的组件职责如下：

### `ResponsiveDataView`

- 接收现有 Table 所需的 `columns`、`dataSource`、`rowKey`、`rowSelection`、`pagination` 和表格配置。
- 测量容器宽度并选择 `full/compact/narrow` 模式。
- `full` 模式渲染 Ant Design `Table`。
- `compact/narrow` 模式渲染卡片列表，向下传递同一条记录和同一套业务回调。

### `ResponsiveCardList`

- 根据页面字段配置组织身份区、状态区、操作区和详情区。
- 支持 `expandedKeys`，默认只展开用户主动打开的记录。
- 输出语义化列表和按钮，不依赖横向滚动。

### 页面适配配置

每个纳入页面只增加轻量配置：主字段、次要字段、详情字段、操作字段和必要的空值处理。数据请求、删除、编辑、发布、同步、批量操作函数不迁移到公共组件。

## 7. 可访问性与兼容性

- 桌面端保留表格语义；卡片端使用列表/区域语义，主名称作为可识别标题。
- 展开按钮提供 `aria-expanded` 和明确的中文 `aria-label`。
- 复选框、操作按钮、更多菜单支持键盘 Tab/Enter/Space。
- 最小点击区域保持 32–36px，避免 Windows 鼠标操作困难。
- 不引入依赖触摸板的手势；触摸设备可直接点击展开和操作。
- 页面根节点禁止横向溢出，长字段只在卡片详情或 Tooltip 中查看。

## 8. 测试与验收

### 自动化测试

- 自适应模式断点测试：1180、1179、760、759px。
- 字段优先级和空值渲染测试。
- 卡片展开/收起、复选框、全选当前页和操作按钮回调测试。
- 仪表盘事业部展开/收起与合计数据回归测试。
- 原前端和 Worker 全量测试、TypeScript 构建。

### 浏览器验收矩阵

- 1536×900：完整表格与现状一致。
- 1280×800：管理页核心字段和操作可见，不出现 body 横向滚动。
- 1024×768：自动进入两列卡片，常用操作在首屏。
- 768×900：单列/窄卡片，详情可展开。
- 390×844：导航抽屉、卡片、按钮和详情均可操作。
- 额外检查浏览器 125%/150% 缩放，确保判断基于内容区实际宽度。

### 验收标准

1. 管理页小屏首次进入不需要横向拖动即可看到主信息和常用操作。
2. 任何原表格字段都能在详情中找到。
3. 现有 API 请求次数、权限和业务回调无变化。
4. 仪表盘上方和招聘日报/简历管理现有布局无回归。
5. 页面没有 body 级横向滚动条；仅允许组件内部用于特殊长文本的局部滚动。

## 9. 分阶段实施与回滚

1. 先实现通用 `ResponsiveDataView`、模式检测和卡片字段渲染测试。
2. 接入需求管理、岗位管理、岗位映射、用户/面试官管理等高频页面。
3. 接入入职、试用期、面试、人才库、工作流、JD、邮件、能力维度和复核页面。
4. 最后接入仪表盘底部明细表，并专门回归事业部展开/收起和合计行。
5. 每阶段独立提交，任一阶段出现问题可回滚到原 `TableViewport + Table` 渲染，不触及后端和生产数据。
