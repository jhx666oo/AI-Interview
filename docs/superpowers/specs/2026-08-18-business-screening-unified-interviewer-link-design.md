# 业务筛选负责人统一链接与岗位筛选设计

## 1. 背景

同一位负责人可能负责多个岗位，且同一负责人会因为新增简历、重复提醒而多次收到飞书消息。当前业务筛选链接已经按负责人复用，但有效期结束后会创建新批次和新链接；业务筛选公开页也没有按岗位切换的筛选控件，导致负责人需要在多个消息和候选人之间反复记忆处理进度。

## 2. 目标

- 同一负责人在不同岗位、不同推送批次、不同提醒消息中，始终使用同一个业务筛选链接。
- 新推送的候选人追加到负责人已有链接中，不创建重复链接。
- 链接按 30 天续期；再次推送或重发时从当前时间重新计算 30 天，但不改变链接地址。
- 飞书提醒展示负责人当前全部待处理数量，并引导进入统一的待筛选工作台。
- 业务筛选页面增加岗位复选筛选，可在同一链接内切换负责人负责的不同岗位。
- 已处理候选人保留在页面中并展示状态，方便区分待处理、已通过和已淘汰。

## 3. 非目标

- 不新增独立“人才库”页面。
- 不改变业务筛选回调的入库/不入库语义、权限校验和幂等规则。
- 不把不同负责人的候选人合并到同一公开链接。
- 不修改仪表盘数据和视觉方案。

## 4. 方案选择

### 方案 A：复用现有负责人批次并续期（采用）

继续使用 `resume_push_batches` 和 `resume_push_batch_items`。负责人作为稳定 scope，首次创建的批次作为该负责人的 canonical batch；后续跨岗位推送、重复提醒和过期后再次推送均复用该批次及其 token，只追加不存在的候选人并刷新 30 天有效期。

优点是改动小、保留现有公开链接和回传链路，历史数据兼容成本最低。需要增加“查找负责人最近可复用批次”和“刷新批次有效期”的存储能力。

### 方案 B：新增负责人链接表

新增负责人到固定 token 的映射表，业务批次只保存历史记录。

优点是链接生命周期与批次历史彻底分离；缺点是要迁移现有链接、重新设计公开页查询和撤销语义，本期投入较大。

### 方案 C：公开页按负责人实时查询所有待处理简历

链接只携带负责人身份，页面实时查询该负责人所有待处理简历。

优点是无需追加批次条目；缺点是公开 token 与负责人范围绑定更复杂，历史已处理记录、岗位范围和回传幂等都需要重新建模，不采用。

## 5. 详细设计

### 5.1 链接与批次

1. 负责人以飞书 `open_id` 作为稳定 scope。
2. 推送时优先查找该 scope 当前有效的批次；没有时查找该负责人历史上最近的未撤销批次，包括已过期批次。
3. 找到批次后复用原 `batch_id`、`token_hash` 和由 scope + batch 生成的 token，不重新生成地址。
4. 批次重新激活，新增候选人通过 `(batch_id, resume_id)` 去重追加。
5. 每次成功推送或重发都把 `expires_at` 更新为当前时间后 30 天；前端仍展示新的到期时间，但 URL 不变。
6. 被 HR 主动撤销的批次不复用，避免被撤销链接重新开放。

### 5.2 飞书消息

每次负责人收到一条消息，消息使用 canonical batch URL。消息内容使用该批次当前待处理条目总数，而不是本次新增条目数，文案调整为“已统一汇总到待筛选列表”，按钮调整为“进入待筛选简历”。岗位标题仍可展示本次涉及的岗位，但不影响链接范围。

### 5.3 公开页岗位筛选

公开页从当前批次候选人中计算唯一岗位列表。增加岗位复选框组：

- 默认选中全部岗位；
- 取消某个岗位后，左侧候选人列表和右侧当前候选人详情只展示选中岗位；
- 每个岗位选项展示“待处理数/总数”；
- 切换岗位不会改变服务端数据，处理动作仍通过原 token 和原候选人 ID 回传；
- 已处理候选人保留并显示状态，待处理候选人继续支持逐份处理和批量处理；
- 当前选中候选人被筛掉时，自动切换到当前筛选结果中的第一份候选人。

## 6. 错误与安全

- 不同负责人始终通过 token 批次隔离，公开页不能读取其他负责人的候选人。
- 过期链接仍返回 410；只有 HR 再次推送/重发时才续期同一批次。
- 撤销批次不被自动复用。
- 批次追加使用唯一约束和现有幂等逻辑，重复消息不会重复展示同一候选人。
- 处理动作继续沿用现有 dispatch group 校验，防止旧消息覆盖新批次结果。

## 7. 验收标准

1. 同一负责人先推送岗位 A，再推送岗位 B，两次返回 URL 完全一致。
2. 同一负责人再次发送提醒，消息中的 URL 完全一致，待处理数量是该负责人当前总待处理数。
3. 模拟批次过期后再次推送，URL 仍完全一致，到期时间刷新为 30 天后。
4. 公开页岗位复选框默认全选，取消某岗位后只显示其他已选岗位候选人。
5. 通过/淘汰后状态保留，切换岗位不会丢失处理状态。
6. 不同负责人之间链接和候选人数据继续隔离。
