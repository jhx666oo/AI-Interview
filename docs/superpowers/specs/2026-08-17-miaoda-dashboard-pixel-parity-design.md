# 妙搭招聘看板视觉一比一迁移设计

## 目标

在不改变现有业务功能、数据接口、权限和同步入口的前提下，将现有系统的 `/dashboard` 视觉和交互结构迁移为妙搭招聘看板的布局。目标是同一桌面视口下，区块顺序、信息层级、颜色、间距、卡片比例、表格分组和操作位置与参考页面一致；系统数据仍由现有 D1、飞书和静态 Excel 快照提供。

## 参考基准

- 第一基准：妙搭招聘看板的滚动长截图，桌面宽度约 1440–1600px。
- 实现基准：用户提供的 `code (2)/client/src/pages/RecruitmentDashboardPage/` 下的页面组件（KPI、漏斗、事业部、HRBP、周动态、字段释义和明细表），优先复用其结构、文案和视觉比例。
- 第二基准：妙搭页面的字段口径说明，决定标签、指标、副文案和漏斗计算。
- 第三基准：现有系统的实时数据和权限行为，不能因视觉迁移丢失筛选、同步、快照、分享、导出和响应式能力。

## 复用边界

妙搭项目本身是独立的 Vite + Tailwind + Nest 应用，不能把整个 `client` 目录覆盖进当前系统，否则会替换现有登录、路由、Cloudflare Worker API 和权限链路。本次采用页面级迁移：复用该项目的页面分区和视觉结构，在当前 Ant Design 应用中用 CSS Modules 实现同等样式，并通过 `DashboardV3Board` 适配数据；现有系统壳层、筛选、同步、快照、分享和导出继续由当前项目负责。

视觉验收以 1440px 桌面视口为主；完成桌面对齐后，再对 13–16 寸笔记本做紧凑布局适配，不要求小屏保留桌面所有列宽。

## 页面结构

1. **顶部标题区**
   - 页面标题：`五大事业部招聘看板 - {月份}`。
   - 显示数据截止日期、自动更新时间。
   - 右侧保留导出 Excel、历史快照、字段口径说明、手动同步、最新数据选择器。
   - 系统现有“从飞书同步”“保存今日快照”“分享看板”“刷新当前数据”继续保留，并映射到同一组按钮。

2. **总体概览**
   - 先显示数据范围提示：P0/P1 进入 KPI，P2 只在储备岗明细出现。
   - 7 张 KPI 卡片：在招岗位、在招人数、简历推送、安排面试、面试通过率、发放 Offer、平均招聘周期。
   - 每张卡片包含主数值、副文案、单位和异常/不可用状态。
   - 下方增加“在途参考”提示条，展示在途岗位数量及平均已耗时。

3. **AI 智能总结 · 全局诊断**
   - 灰底、红色左边框、三条编号式诊断文案。
   - 文案由现有 `insights.summary`、`bottlenecks`、`recommendations` 组合生成，不能写死截图数字。

4. **全局招聘漏斗**
   - 使用 7 级漏斗：简历推送 → 安排1面 → 1面通过 → 2面通过 → 终面通过 → 发放 Offer → 已入职。
   - 视觉采用居中漏斗形状而非当前横向进度条。
   - 每级显示数量、相对上一级转化率；入口转化率显示 100%。
   - 终面通过沿用后端口径：有 3 面通过时取 3 面，否则取 2 面。

5. **本周招聘动态**
   - 大卡片展示在招岗位数和本周新增岗位数。
   - 下方 7 个小卡片展示新增简历、安排面试、1 面通过、2 面通过、终面、Offer、入职。
   - 保留刷新按钮、基准日期和快照差异说明。

6. **事业部分部看板**
   - 采用 2 列卡片布局，和参考页面一致。
   - 每张卡片显示事业部、HRBP、在招岗位、在招人数、P0 岗位、P0 在招人数、已完结平均周期、简历推送、安排1面、面试通过率。
   - 卡片底部显示 6 级事业部漏斗：简历推送 → 安排1面 → 1面通过 → 2面通过 → Offer → 入职。
   - 小屏自动变为单列，不能产生页面级横向溢出。

7. **招聘效能（按 HRBP）**
   - 采用 3 列卡片布局。
   - 每张卡片显示负责人、所属事业部、负责岗位、在招人数、平均周期、P0 岗位、P0 在招人数和在途参考。
   - 底部显示 5 个节点：简历、1面、终面、Offer、入职，并显示 4 段转化率。
   - 转化率颜色遵循：≥30% 绿色、≥15% 橙色、>0 红色、=0 灰色。

8. **字段释义**
   - 用参考页面的编号列表展示数据范围、漏斗、周期和新增口径。
   - 内容以系统实际实现的计算口径为准，可通过现有字段口径说明入口打开。

9. **全量岗位明细**
   - 至少拆成“在途招聘中”“P2 储备岗”“已完结”三个区块。
   - 每个区块沿用现有 `ResponsiveDataView` 的桌面表格/小屏卡片双模式。
   - 桌面表格支持按事业部折叠展开，保留表头、累计小计、总计和转化率进度条。
   - P2 不进入上方 KPI、漏斗、事业部和 HRBP 统计，只在 P2 区块展示。

## 数据映射

视觉组件只消费 `DashboardV3Board`，不直接读取 D1 或飞书。现有后端继续负责：

- 静态 Excel 快照作为可用基准数据。
- 飞书数据作为主数据源（权限恢复后由“从飞书同步”刷新）。
- D1 简历与流程数据叠加到对应岗位。
- 无法匹配的系统记录进入现有提示，不阻断页面渲染。

需要补齐/确认的展示字段：

- `weekly_dynamic` 映射到“本周招聘动态”。
- `in_progress_average_elapsed_days` 映射到“在途参考”。
- `insights` 映射到 AI 诊断三条文案。
- `positions` 按优先级、状态、事业部拆分为明细区块。

## 样式系统

- 页面底色：参考页面的浅灰冷色背景。
- 内容卡片：白底、细灰边框、轻阴影、统一圆角。
- 主强调色：妙搭页面的红色左侧章节标记和红色顶部 KPI 边框。
- 辅助色：灰蓝文字、绿色成功、橙色警示、红色风险、浅蓝链接。
- 标题、数字、说明文字建立三层字号体系，避免当前页面中不同组件各自定义字号。
- 所有颜色、间距、圆角、卡片阴影集中在 `dashboard.module.css` 的 v3 变量/类中，避免散落内联样式。

## 响应式与交互

- 1440px 以上：严格按参考页面的 7 卡 KPI、2 列事业部、3 列 HRBP 展示。
- 1024–1439px：KPI 自动降为 4+3 两行，事业部保持 2 列，HRBP 降为 2 列。
- 768–1023px：KPI 2 列，所有业务卡片单列；岗位明细使用卡片模式。
- 小屏保留筛选、同步、快照、分享和折叠功能，避免依赖水平滚动才能完成主要操作。
- 桌面明细表可以横向滚动，但必须显示可见滚动提示；固定关键列，右侧操作不被裁切。
- 数据加载失败时显示明确错误状态，并保留旧版看板兜底，不展示空白页面。

## 实施顺序

1. 建立视觉 tokens 和页面骨架，先完成标题区、概览、诊断、漏斗。
2. 重做周动态、事业部卡片和 HRBP 卡片。
3. 重做三组岗位明细及折叠/展开、总计和小屏卡片。
4. 连接现有 v3 数据，不改 API 契约；补齐筛选后的局部统计。
5. 使用固定快照数据做桌面视觉回归，再用真实登录数据验证同步、筛选、分享、导出和小屏布局。

## 验收标准

- 1440px 截图与参考页面的区块顺序、主色、卡片布局、漏斗形状和表格分组一致。
- KPI、漏斗、事业部、HRBP、岗位明细均来自运行时数据，不存在写死截图数字。
- P2 岗位不会进入 KPI、漏斗、事业部和 HRBP 统计。
- D1 叠加简历数、飞书同步、静态快照、筛选、导出、分享功能均保持可用。
- 13–16 寸笔记本上主要信息可直接阅读，页面不出现不可发现的横向溢出。
- 前端构建、Worker 测试、视觉回归和生产 API 检查全部通过。
