# 业务端简历推送与筛选流程需求设计

> 文档版本：v1.0  
> 会议依据：2026-08-12「AI 智能招聘系统」产品总结  
> 设计日期：2026-08-12  
> 当前状态：需求设计，尚未进入实现

## 1. 背景与目标

当前系统已经能够完成简历上传、解析、AI 初筛、HR 入库和面试管理，但“AI 初筛通过”到“业务面试官确认”的过程缺少明确的触达和结果回写机制。HR 无法高效地把一批简历交给指定面试官，也无法在系统内准确区分以下状态：

- AI 初筛是否通过；
- HR 是否已经推送给业务面试官；
- 业务面试官是否已经处理；
- 业务面试官是否筛选通过；
- 候选人是否进入后续面试流程。

本期目标是建立一条清晰、可追踪、支持批量操作的业务端简历筛选链路：

```text
AI 初筛通过
  → HR 推送
  → 面试官专属链接
  → 面试官业务筛选
  → 入库 / 不入库
  → 进入面试管理或结束流转
```

## 2. 本期范围

### 2.1 本期必须实现

1. 岗位管理增加或完善默认面试官配置。
2. 简历管理将“入库/不入库”调整为“推送/淘汰”。
3. 按岗位配置的面试官分组生成推送任务。
4. 为面试官生成包含其全部相关简历的专属链接。
5. 通过飞书向对应面试官发送推送链接。
6. 面试官通过链接查看简历，并执行“入库/不入库”。
7. 面试官操作通过回调写回原简历记录。
8. HR 可以在简历管理中查看推送状态和业务筛选结果。
9. 保留后续仪表盘所需的数据口径和事件数据。

### 2.2 本期暂不实现

- 仪表盘风格修改和 API 接入。仪表盘需等待产品侧完成视觉和 API 后再开发。
- 新增独立“人才库”页面或中间库。当前统一使用已有简历管理/已入库数据承载业务筛选结果。
- 完整的多角色权限体系。第一版不要求面试官登录招聘系统。
- 复制飞书招聘的完整招聘流程。
- 飞书招聘报表的正式抓取实现。该项作为后续独立模块，等待 API 权限、报表入口和字段确认。
- 飞书卡片回调作为唯一入口。卡片方案可以并行验证，但不能阻塞链接推送方案上线。

## 3. 当前项目基础与改造点

### 3.1 已有基础

当前项目已经具备以下相关能力：

- `positions` 表已有 `primary_interviewer`、`secondary_interviewer` 字段。
- 简历已有 AI 初筛结果、`approved`/`rejected` 状态和入库、淘汰接口。
- 已有面试管理和面试官配置能力。
- 已有飞书面试提醒发送逻辑，可以复用飞书身份映射和消息发送能力。
- 已有简历详情、解析文本、AI 评分和原件访问能力。
- 已有操作日志能力，可以记录推送、回调和状态变化。

### 3.2 本期需要新增或调整

- 增加“业务筛选”状态，不能继续只用 AI 初筛的 `screening_result` 表达完整流程。
- 增加推送批次和面试官链接数据。
- 将 HR 的主操作从“入库/不入库”改成“推送/淘汰”。
- 推送成功后，前端按钮和状态切换为“等待面试官处理”。
- 增加公开或半公开的面试官链接页面及安全回调接口。
- 将回调结果与原简历、岗位、推送批次建立可追溯关联。

## 4. 目标业务流程

### 4.1 HR 侧流程

```text
1. 简历完成 AI 初筛
2. 仅 AI 初筛通过且未被 HR 淘汰的简历可推送
3. HR 选择一份或多份简历
4. 点击“推送”
5. 系统按岗位配置的面试官分组
6. 每个面试官生成一条本批次专属链接
7. 系统通过飞书将链接发送给对应面试官
8. 简历状态变为“待业务筛选”
9. HR 在简历管理查看面试官处理进度
10. 面试官处理后，系统回写业务筛选结果
```

### 4.2 面试官侧流程

```text
1. 面试官收到飞书消息
2. 点击专属链接
3. 查看本次推送给自己的全部简历
4. 打开候选人详情和简历原件
5. 点击“入库”或“不入库”
6. 可填写业务筛选备注
7. 系统返回处理成功和当前状态
```

### 4.3 简历进入下一环节

- 面试官点击“入库”：简历标记为业务筛选通过，并进入简历管理的已入库/后续面试候选范围。
- 面试官点击“不入库”：简历标记为业务筛选不通过，不进入后续面试流程，但保留历史记录和处理结果。
- HR 点击“淘汰”：简历直接结束当前招聘流转，不向面试官发送。
- 业务筛选完成后，面试管理创建或展示候选人时，默认读取岗位配置的面试官。

## 5. 简历管理交互需求

### 5.1 操作按钮

当前按钮：

```text
入库 / 不入库
```

本期调整为：

| 当前阶段 | HR 可见操作 | 结果 |
|---|---|---|
| AI 初筛通过，未推送 | 推送、淘汰 | 推送给面试官，或 HR 直接淘汰 |
| 已推送，等待面试官处理 | 查看推送详情、复制链接、重新发送 | 不允许重复生成无关联的新批次 |
| 面试官已入库 | 查看业务筛选结果、进入面试管理 | 业务筛选通过 |
| 面试官不入库 | 查看不入库原因/备注 | 业务筛选不通过 |
| AI 初筛不通过 | 查看原因、淘汰/保留记录 | 不允许直接推送 |
| 已淘汰 | 查看淘汰原因 | 不参与推送 |

### 5.2 推送前置条件

只有同时满足以下条件时，简历才允许推送：

1. AI 初筛结果为“通过”。
2. HR 未将其标记为淘汰。
3. 简历已关联岗位或可解析出标准岗位。
4. 标准岗位已配置至少一名面试官。
5. 简历不处于已推送且等待处理状态，除非 HR 明确选择重新发送。

如果任一条件不满足，系统应明确提示原因，不发送飞书消息。

### 5.3 批量推送

- 支持在简历管理中选择多份简历后批量推送。
- 系统按“目标面试官”分组；同一批次可以生成多个面试官链接。
- 一个面试官在同一批次只收到一条链接，链接内包含本批次与其相关的全部简历。
- 部分简历缺少岗位面试官时，不应阻塞其他可推送简历；系统应返回成功、跳过和失败明细。
- 推送操作完成后，前端立即显示提交结果，后台继续完成消息发送和状态刷新。

## 6. 岗位管理需求

### 6.1 面试官字段

岗位管理需要提供：

- 一面/业务筛选面试官；
- 二面面试官；
- 如产品后续确认需要，可扩展终面面试官，但不纳入本期必做范围。

### 6.2 选择与保存

- 优先使用面试官下拉选择，不建议继续依赖自由文本。
- 保存面试官姓名和飞书 `open_id` 的稳定映射。
- 岗位编辑时展示当前已保存的面试官。
- 面试官被停用或无法匹配飞书身份时，保存可以保留历史值，但推送前必须提示不可发送。
- 岗位未配置面试官时，简历推送按钮应给出“请先配置岗位面试官”的明确提示。

### 6.3 面试管理默认值

当业务筛选通过的简历进入面试管理时：

- 自动读取简历对应标准岗位的面试官配置；
- 自动填充一面/业务筛选面试官和二面面试官；
- HR 可以在实际安排面试时调整，但调整不反向修改岗位默认配置；
- 面试记录保存最终实际使用的面试官，保证历史记录稳定。

## 7. 面试官专属链接

### 7.1 页面内容

面试官链接应展示本次推送中与该面试官相关的全部简历。每个候选人至少展示：

- 姓名；
- 标准岗位；
- 学历；
- 年龄；
- 性别；
- 城市；
- 专业；
- AI 初筛结论；
- AI 总分和能力维度评分；
- 个性化需求匹配结果；
- 简历解析文本；
- 简历原件预览或下载入口；
- 业务筛选状态；
- 业务筛选备注；
- 入库、不入库操作。

### 7.2 链接形态

- URL 使用不可预测的随机 Token，不直接暴露简历 ID、数据库 ID 或飞书记录 ID。
- 链接对应一个“推送批次 + 面试官”，而不是只对应一份简历。
- 同一链接打开后可看到该面试官本次批次的全部候选人。
- 链接失效后只能查看失效提示，不允许继续提交回调。
- 第一版可以不要求面试官登录，但必须限制数据范围：链接只能访问关联批次中的简历。

### 7.3 链接生命周期

建议默认有效期为 7 天，支持 HR 重新发送时生成新的访问凭证。系统应记录：

- 创建时间；
- 失效时间；
- 首次访问时间；
- 最近访问时间；
- 发送次数；
- 面试官处理完成时间；
- 是否主动撤销。

## 8. 回调接口与幂等规则

### 8.1 逻辑接口

接口名称可按现有 Worker 路由规范实现，逻辑上需要支持：

```text
GET  /api/business-screening/:token
POST /api/business-screening/:token/resumes/:resumeId/approve
POST /api/business-screening/:token/resumes/:resumeId/reject
```

请求体可以包含：

```json
{
  "remark": "业务筛选备注"
}
```

### 8.2 回调校验

每次回调必须校验：

1. Token 存在且未过期。
2. 简历属于该 Token 对应的推送批次。
3. 面试官与该批次匹配。
4. 简历当前允许进行业务筛选。
5. 请求动作是允许的 `approve` 或 `reject`。

### 8.3 幂等行为

- 对同一份简历重复点击同一结果，返回成功且不重复写入。
- 已入库后再次点击不入库，应提示“该简历已处理”，不覆盖已有结果。
- 已不入库后再次点击入库，应提示“该简历已处理”，如需改判由 HR 在系统内执行人工变更。
- 回调成功后立即更新链接中的状态，避免面试官重复操作。
- 所有回调写入操作日志，记录批次、简历、面试官、动作和时间。

## 9. 建议数据模型

### 9.1 简历业务状态

不建议把业务筛选结果继续塞入 AI 初筛字段。建议新增独立字段，或使用等价的结构化字段：

| 字段 | 说明 |
|---|---|
| `business_screening_status` | `not_ready`、`pending`、`passed`、`rejected` |
| `business_screening_remark` | 面试官业务筛选备注 |
| `business_screened_at` | 业务筛选完成时间 |
| `business_screened_by` | 面试官标识/姓名 |
| `hr_disposition` | HR 处置结果，如 `pending`、`pushed`、`rejected` |

### 9.2 推送批次

建议新增 `resume_push_batches`：

| 字段 | 说明 |
|---|---|
| `id` | 批次 ID |
| `interviewer_id` | 面试官用户 ID，可为空 |
| `interviewer_name` | 面试官姓名 |
| `interviewer_open_id` | 飞书 open_id |
| `token_hash` | 链接 Token 哈希，不保存明文 Token |
| `expires_at` | 失效时间 |
| `status` | `active`、`completed`、`revoked`、`expired` |
| `created_by` | 创建推送的 HR |
| `created_at` | 创建时间 |
| `last_sent_at` | 最近发送时间 |

### 9.3 批次明细

建议新增 `resume_push_batch_items`：

| 字段 | 说明 |
|---|---|
| `id` | 明细 ID |
| `batch_id` | 推送批次 ID |
| `resume_id` | 简历 ID |
| `position_id` | 岗位 ID |
| `status` | `pending`、`passed`、`rejected` |
| `remark` | 面试官备注 |
| `processed_at` | 处理时间 |
| `created_at` | 创建时间 |

### 9.4 数据约束

- `batch_id + resume_id` 唯一，避免同一批次重复加入简历。
- 一个批次只对应一个面试官；一次 HR 批量推送可产生多个面试官批次。
- 业务筛选结果必须能追溯到最后一次有效推送批次。
- 删除或淘汰简历时，不删除历史推送日志和处理记录。

## 10. 飞书发送规则

### 10.1 发送内容

飞书消息至少包含：

- 业务标题：待筛选简历推送；
- 面试官姓名；
- 本次待处理简历数量；
- 目标岗位摘要；
- 专属链接；
- 链接有效期；
- 处理说明。

### 10.2 发送失败

- 面试官没有可用 `open_id`：该组标记失败并提示 HR 配置面试官。
- 用户 Token 失效：提示重新绑定飞书，不将消息静默改发给其他人。
- 单个面试官发送失败：不影响其他面试官分组的发送。
- 消息发送失败后允许 HR 重试，但重试应复用同一批次或明确生成新批次，不能产生无法追踪的重复状态。

### 10.3 卡片回调

飞书卡片回调作为可选增强方案：

- 先验证海外服务器部署环境下的飞书回调可达性；
- 卡片操作必须复用同一套业务筛选回调服务；
- 卡片不可用时，链接推送仍然是完整可用的主流程；
- 不因为卡片回调未验证而阻塞链接推送上线。

## 11. 状态流转

### 11.1 推荐状态

```text
AI 初筛中
  ↓
AI 初筛通过 / 待推送
  ├─ HR 淘汰 → HR 淘汰
  └─ HR 推送 → 待业务筛选
                    ├─ 面试官入库 → 业务筛选通过 → 面试管理
                    └─ 面试官不入库 → 业务筛选不通过
```

### 11.2 状态显示

| 状态 | 前端展示 | 允许操作 |
|---|---|---|
| AI 初筛通过 | 待推送 | 推送、淘汰 |
| 已推送 | 待业务筛选 | 查看链接、复制链接、重新发送 |
| 业务筛选通过 | 业务已通过 | 查看、进入面试管理 |
| 业务筛选不通过 | 业务不通过 | 查看备注 |
| HR 淘汰 | 已淘汰 | 查看淘汰原因 |
| AI 初筛不通过 | AI 不通过 | 查看评分和原因 |

## 12. 仪表盘预留口径

仪表盘暂不开发，等待产品侧完成风格和 API。后续接入时使用以下口径：

| 产品指标 | 业务含义 | 推荐数据事件/字段 |
|---|---|---|
| AI 初筛通过 | AI 初筛通过的简历数量 | `screening_result = 通过` |
| 一面通过数 | 产品总结约定为 AI 初筛通过数 | AI 初筛通过结果 |
| 业务筛选通过 | 面试官点击入库的简历数量 | `business_screening_status = passed` |
| 二面面试数 | 人才库业务通过数量 | 业务筛选通过后进入面试管理的数量 |
| 二面通过数 | 面试管理中的二面通过数量 | 二面面试结果为通过 |

产品 API 准备完成后，另行补充：API 地址、鉴权方式、字段映射、刷新频率、异常兜底和验收样例。

## 13. 飞书招聘报表抓取

该项作为后续独立需求，不阻塞本期推送流程。待权限和接口明确后，优先确认以下内容：

- 报表入口或飞书招聘 API；
- 目标报表和数据范围；
- 岗位、简历、面试和入职字段；
- 岗位开始/结束周期；
- 报表中业务筛选通过与二面数据的对应字段；
- 全量同步或增量同步；
- 同步频率和失败重试；
- 数据写入 D1、飞书多维表格或产品 API 的目标位置。

第一版建议先只读抓取并保存原始响应和同步时间，完成字段核对后再参与仪表盘计算，避免未经核对的数据直接影响指标。

## 14. 异常与安全要求

### 14.1 数据安全

- Token 使用高强度随机值，数据库只保存哈希。
- 链接页面只返回该面试官、该批次关联的简历。
- 不在 URL、日志或错误信息中暴露简历 ID、手机号、邮箱等敏感信息。
- 简历原件访问继续复用现有受控下载逻辑。
- 链接失效、撤销或批次完成后不可继续修改结果。

### 14.2 业务异常

- 岗位没有面试官：推送前阻断并提示配置。
- 简历没有标准岗位：推送前阻断并提示补充岗位映射。
- 简历已经被其他批次处理：页面展示当前状态，不覆盖已有业务结果。
- 面试官重复点击：按幂等规则处理。
- 部分消息发送失败：返回逐项结果，支持只重试失败组。
- 面试官链接打不开：提示链接已过期、已撤销或无权限，不返回具体候选人信息。

## 15. 验收标准

### 岗位管理

- 可以为岗位选择并保存默认一面/业务筛选面试官。
- 简历推送时能够读取岗位对应面试官。
- 面试管理新建面试时默认带出岗位面试官。

### 简历管理

- AI 初筛不通过的简历不能推送。
- AI 初筛通过且未淘汰的简历可以单条和批量推送。
- 推送成功后不再显示原“入库/不入库”操作，显示等待业务筛选状态。
- HR 可以执行“淘汰”，且淘汰简历不会发送给面试官。

### 面试官链接

- 一个面试官链接可以查看本批次全部相关简历。
- 页面能查看简历解析和原件。
- 面试官可以对每份简历执行入库或不入库。
- 操作结果能显示成功状态和业务筛选备注。

### 回调与同步

- 入库回调能更新原简历并进入面试管理候选范围。
- 不入库回调能更新原简历为业务筛选不通过。
- 重复回调不会造成重复入库或状态反复覆盖。
- HR 刷新简历管理后可以看到业务筛选结果。
- 推送、发送、访问、回调均有操作日志。

### 不在本期验收

- 仪表盘视觉和 API 接入；
- 飞书招聘报表正式同步；
- 飞书卡片回调在海外部署环境中的最终可用性；
- 多角色权限体系。

## 16. 建议开发顺序

1. 明确岗位面试官字段和飞书身份映射。
2. 增加简历业务筛选状态和推送批次数据模型。
3. 改造简历管理按钮和状态展示。
4. 实现按面试官分组的批量推送服务。
5. 实现面试官链接页面。
6. 实现入库/不入库回调与幂等控制。
7. 接入飞书链接消息发送和失败重试。
8. 接通业务筛选通过到面试管理的默认面试官流程。
9. 补充单元测试、接口测试和链接安全测试。
10. 等产品 API 和视觉稿确定后，再单独开发仪表盘。
11. 待飞书招聘权限和报表字段确认后，再开发报表抓取。

## 17. 关键决策记录

| 决策 | 结论 |
|---|---|
| 是否新增独立人才库页面 | 暂不新增，统一在现有简历管理中承载 |
| HR 首次操作名称 | 推送 / 淘汰 |
| 面试官处理名称 | 入库 / 不入库 |
| 推送方式 | 优先链接推送，卡片回调并行验证 |

| 仪表盘开发时机 | 等产品风格和 API 完成后再开发 |
| 飞书招聘报表 | 作为后续独立模块，不阻塞本期流程 |
