# 简历统一重处理流程设计

## 背景

当前简历存在多套 AI 处理入口：上传后的队列处理、单份“AI 初筛”、单份“重新解析”、批量自动评估、批量 AI 评估和批量重解析。它们使用的提示词、岗位上下文来源和结果保存方式不完全一致，导致同一份简历在不同入口得到不同的能力维度结果，已有评估也可能继续沿用旧提示词生成的内容。

## 目标

1. 上传后处理、单份重新评估、批量重新评估复用同一条异步队列流程。
2. 评分时统一读取标准岗位、岗位职责、岗位要求、个性化需求、能力维度名称、权重和描述。
3. 评分结果只保留岗位当前配置的能力维度，并按维度名称去重，避免模型额外生成无关维度。
4. 重新评估只覆盖解析和 AI 评估结果，不修改 HR 复核、入库、淘汰等人工状态。
5. 正在处理的简历不重复创建任务，失败任务可再次触发。

## 方案

### 统一队列

复用现有 `resume-processing` 队列和消费者。单份重新评估及批量重新评估只负责：

1. 校验简历存在并确认没有同一简历的活动任务。
2. 清理旧的解析结果和 AI 评估结果，保留 PDF、原文、岗位和人工决策字段。
3. 将 `parse_status` 设为 `queued`，创建或重置处理任务。
4. 投递 `{ jobId, resumeId }` 到 `resume-processing` 队列。
5. 立即返回 202 及任务信息，前端沿用现有轮询刷新状态。

消费者继续负责 OCR/文本读取、字段提取、基础初筛和能力维度专项评分，避免在 HTTP 请求中同步调用 AI 导致超时。

### 统一岗位上下文

抽取一个共享的岗位上下文加载器，按标准岗位名读取：

- `positions.description`
- `positions.requirements`
- `positions.personalized_requirements`
- `capability_dimensions.dimensions_json`（优先）
- `positions.capability_dimensions`（兼容兜底）
- 维度的 `name`、`description`、`weight`

所有评分入口都使用同一份上下文。岗位映射失败时保留原岗位名并将结果标记为待复核，不静默使用其他岗位的维度。

### 统一评分结果

能力评分提示词要求模型逐项评估给定维度，但服务端不信任模型自行扩展的维度集合。保存前执行：

- 以岗位配置维度名称建立白名单；
- 规范化名称、分数和理由；
- 丢弃不在白名单中的维度；
- 对缺失的配置维度补发一次只针对缺失项的评分请求；
- 最终按配置顺序保存 `dimensions`，同时保存 `configured_dimensions` 和权重。

无岗位能力维度时，结果不生成“通用维度”，而是保存空维度并提示“岗位未配置能力维度”，避免不同简历出现不可比较的维度集合。

## 前端入口调整

### 简历详情页

- 删除“AI 初筛”按钮，避免继续调用旧的同步 `/ai-screen` 路径。
- 保留“重新解析”按钮并改名为“重新评估”。它触发统一队列流程，说明文案改为“重新提取简历并按当前岗位配置重新评分”。
- 处理中时禁用该按钮；完成或失败后显示最终状态，失败可再次触发。

### 简历管理页

- 删除“AI 自动评估”。
- 删除“AI 批量评估”。
- 将“全部重解析”改为“批量重新评估”。
- 有勾选简历时只处理勾选项；未勾选时二次确认后处理全部简历。
- 批量操作只提交任务，页面通过现有轮询显示处理进度，不等待所有 AI 请求完成。

旧接口保留兼容，但内部统一转为队列任务，避免历史前端或外部调用继续触发旧评分逻辑。

## 数据和状态语义

重新评估时清理：`ai_review`、`ai_evaluation`、`match_score`、`screening_result`、`hard_requirement_result`、字段解析结果及相关处理错误。

重新评估时保留：简历 PDF/原文、候选人、岗位、负责人、HR 复核、入库/淘汰状态、面试关联和操作记录。

任务状态沿用现有状态机：`queued` → `extracting_text` → `extracting_fields` → `screening` → `ai_screened`，失败进入 `failed` 并记录错误原因。

## 兼容与错误处理

- 使用现有活动任务幂等机制，重复点击返回当前任务，不重复消耗 AI 额度。
- 简历没有 PDF 或文本时，任务进入失败并返回可读原因；不覆盖原始文件。
- 岗位不存在或未配置能力维度时仍完成字段解析和基础评估，能力维度区块显示未配置提示。
- 旧的同步接口不再直接调用 AI；转换入队失败时返回明确错误，不伪造“评估完成”。

## 测试计划

1. Worker 单元测试：重新评估会清理旧 AI 结果、创建任务并发送队列消息。
2. Worker 单元测试：重复触发活动任务不会创建第二个任务。
3. Worker 单元测试：维度白名单过滤额外维度、去重并按配置顺序补齐缺失项。
4. Worker 单元测试：岗位上下文优先使用独立能力维度表，并保留描述和权重。
5. 前端测试：详情页只显示“重新评估”；列表页只保留“批量重新评估”。
6. 现有 Worker 测试、前端构建和生产前置检查全部通过。

## 非目标

- 本次不修改岗位管理页面的数据模型和录入交互。
- 本次不自动重评所有历史简历；由用户通过单份或批量重新评估触发。
- 本次不修改 HR 的人工审核和入库规则。
