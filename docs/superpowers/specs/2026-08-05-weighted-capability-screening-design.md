# 简历能力维度加权初筛设计

## 目标

统一简历上传、重新解析、自动评估和批量重评的评分口径：AI 按岗位配置的能力维度逐项输出 0–5 分，后端负责准入闸门、加权分和二值初筛结果。简历编辑页的“匹配度”显示 0–5 的加权分，不再显示旧的 0–100 百分比。

## 评分维度

前端现有 7 个能力维度保持不变：

1. 核心画像
2. 核心职责
3. 任职要求
4. 企业背景
5. 关键词匹配
6. 加分项
7. 避坑雷区

“关键词匹配”和“避坑雷区”只作为准入闸门，不进入最终加权分。其余 5 个维度参与加权：核心画像、核心职责、任职要求、企业背景、加分项。

默认原始权重为 `25 / 22 / 22 / 13 / 10`，计算时按岗位实际配置归一化到 100%。岗位管理可分别调整这 5 个参与加权的维度；关键词匹配和避坑雷区保留独立评分和展示，但不影响加权分权重。

## 判定流程

```text
AI 输出 7 个维度（每项 0–5）
        |
        +-- 关键词匹配 < 5 ------> AI 不通过（原因：关键词未达满分）
        |
        +-- 避坑雷区 < 5 --------> AI 不通过（原因：命中避坑雷区）
        |
        +-- 两项均为 5 ----------> 计算其余 5 项加权分
                                      |
                                      +-- 加权分 >= 4.0 -> 通过
                                      +-- 加权分 <  4.0 -> 不通过
```

对准入失败的候选人不计算最终加权分，持久化 `weighted_score = null`，但保留 7 项明细和失败原因，方便前端解释。

## 数据契约

AI 评估 JSON 至少包含：

```json
{
  "dimensions": [
    {"name": "核心画像", "score": 0, "reason": ""},
    {"name": "核心职责", "score": 0, "reason": ""},
    {"name": "任职要求", "score": 0, "reason": ""},
    {"name": "企业背景", "score": 0, "reason": ""},
    {"name": "关键词匹配", "score": 0, "reason": ""},
    {"name": "加分项", "score": 0, "reason": ""},
    {"name": "避坑雷区", "score": 0, "reason": ""}
  ],
  "weighted_score": 0,
  "screening_reason": "关键词未达满分"
}
```

后端会按名称匹配岗位配置，过滤 AI 多返回或缺失的维度；缺失的闸门维度按 0 分处理，防止绕过准入规则。最终 `screening_result` 只允许 `通过` 或 `不通过`，由后端根据闸门和 `weighted_score >= 4` 计算，不采信 AI 自己返回的推荐标签或旧 `match_score`。

旧的 `match_score` 字段保留用于兼容历史 API，但新的列表、详情和初筛判定使用 `weighted_score`。历史数据重评后，`match_score` 同步写入 0–5 加权分，避免前端继续读取旧百分比。

## 前端展示

- 简历列表、简历编辑页和相关详情统一显示 `加权分 / 5`。
- 7 个维度继续以现有标签/卡片展示。
- “关键词匹配”和“避坑雷区”单独突出显示，展示分数、理由和最终失败原因。
- 不再展示“AI 存疑”；空值只表示尚未完成评估或仍在处理中。

## 历史简历重评

部署后通过现有简历处理队列批量重新评估全部历史简历，复用上传、重新解析和自动评估的统一流程。任务按批次入队、可重试、可观测，避免单次 HTTP 请求超时。重评只更新 AI 评估、能力分、加权分、初筛结果和解析状态，不修改原始 PDF、OCR 文本、人工复核和面试记录。

## 测试与验收

- 单元测试覆盖：闸门 `<5`、闸门 `=5`、加权分边界 `3.9/4.0`、缺失维度、旧数据归一化。
- Worker 测试覆盖所有评估入口（上传、重新解析、批量评估、队列消费者）都调用同一评分函数。
- 前端测试覆盖加权分显示为 `/5`、闸门失败原因展示和旧 `match_score` 不再作为主显示值。
- 构建、预发布检查和线上健康检查通过后才允许生产部署。
