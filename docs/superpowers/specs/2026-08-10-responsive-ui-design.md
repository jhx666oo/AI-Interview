# 响应式界面改造设计

## 背景

当前前端基于 React 19、Vite 7 和 Ant Design 6。业务功能已经覆盖需求、岗位、简历、面试、入职、招聘日报和系统设置，但页面主要按照桌面宽度实现。浏览器放大后，可用 CSS 宽度变小，固定侧边栏、固定间距、不可换行的 Flex 区域和宽表格会共同导致标题截断、姓名逐字换行、按钮溢出以及页面级横向滚动。

问题主要来自应用自身的布局约束，不需要更换 React、Vite 或 Ant Design，也不需要修改后端接口、数据库或业务状态机。

## 目标

- 在 100%、125%、150%、175% 和 200% 浏览器缩放下保持可用。
- 在 1920、1440、1280、1024、768 和 390 CSS 像素宽度下保持可用。
- 页面本身不产生横向滚动；宽表格只在表格容器内横向滚动。
- 标题、用户名、按钮、标签和候选人姓名不被截断或压成竖排。
- 保留现有接口、字段、权限、筛选、分页、上传、AI 评估和批量操作行为。
- 桌面宽屏下保持现有颜色、圆角、间距层级和整体视觉风格。
- 改造可以分阶段发布，并能通过 Git 提交快速回滚。

## 非目标

- 不更换前端技术栈。
- 不重写页面业务逻辑。
- 不修改 API 请求和响应协议。
- 不修改 D1、队列、R2、飞书或 AI 配置。
- 不用 `zoom`、`transform: scale()` 或禁止浏览器缩放来掩盖布局问题。

## 设计决策

采用“渐进式响应改造”：先修复应用骨架和全局容器，再迁移高频页面，最后覆盖低频页面。新布局只改变排版和收纳方式，不改变用户可以完成的业务操作。

### 响应式断点

| 可用 CSS 宽度 | 页面模式 | 侧边栏 | 顶部栏 | 内容策略 |
| --- | --- | --- | --- | --- |
| `>=1200px` | 桌面 | 200px 展开 | 标题、负责人、通知、用户信息完整显示 | 保持现有桌面结构 |
| `768-1199px` | 紧凑 | 80px 图标模式 | 隐藏用户名等次要文本 | 工具栏换行，卡片两列 |
| `<768px` | 窄屏 | 隐藏，使用抽屉 | 菜单、标题、通知、头像 | 卡片单列，表单单列 |
| `<480px` | 极窄 | 抽屉 | 标题省略，次要操作收纳 | 控件全宽，操作分组换行 |

浏览器缩放不单独处理。缩放改变 CSS 视口宽度后，使用同一套断点，保证无障碍缩放不被绕过。

## 应用骨架

### Layout

修改 `frontend/src/components/Layout/index.tsx`，保留现有路由、菜单权限和负责人列表逻辑。

- 给外层 Layout、内容 Layout 和 Content 增加 `min-width: 0`，避免子元素把整个页面撑宽。
- 抽取 `isCompact` 和 `isMobile` 两种展示状态；状态只决定排版，不参与权限或数据请求。
- 桌面模式继续使用固定侧边栏。
- 紧凑模式自动使用折叠侧边栏，同时保留用户手动展开/折叠能力。
- 窄屏模式隐藏 Sider，顶部增加菜单按钮，通过抽屉展示原有菜单项。
- 抽屉跳转后自动关闭，不改变当前路由行为。

### Header

将顶部区域拆成左、中、右三个可收缩区域：

- 左侧为移动菜单按钮和页面标题。
- 中间为负责人选择器。
- 右侧为通知和用户菜单。

空间不足时按以下顺序收缩：

1. 隐藏用户名，只保留头像。
2. 负责人选择器改为筛选按钮和弹出面板。
3. 页面标题单行省略。

不再依赖固定 `line-height: 64px` 来实现垂直对齐，避免高倍缩放时文字溢出 Header。

### Content

内容边距使用响应式变量：桌面 32px、中屏 24px、小屏 16px、极窄屏 12px。页面容器设置 `max-width: 100%` 和 `min-width: 0`，并禁止应用根容器产生横向滚动。

## 通用布局组件

新增只负责布局的组件，不在组件内写业务请求或业务判断。

### `PageHeader`

统一处理页面标题、说明文本、主操作按钮和辅助操作按钮。大屏横向排列，中屏自动换行，小屏按优先级分组。

### `ResponsiveToolbar`

统一处理搜索、筛选、批量操作和重置按钮。筛选项使用自适应网格，操作按钮独立成组；不再把大量控件塞进 Ant Design Card 的 `extra` 区域。

### `ResponsiveTable`

统一包装 Ant Design Table：

- 横向滚动限制在表格容器内部。
- 使用 `min-width: 0` 修正 Flex 子元素宽度计算。
- 桌面使用正常密度，小屏降低单元格内边距。
- 选择框、主标识列和操作列按页面需要冻结。
- 不删除业务列；无法在窄屏完整显示的列通过内部滚动访问。

### `ResponsiveModal`

统一弹窗最大宽度和内容滚动：

- 实际宽度不得超过 `calc(100vw - 32px)`。
- 桌面保留原有弹窗宽度。
- 窄屏表单从两列/三列切换为单列。
- 只让弹窗内容滚动，避免整个页面被弹窗撑宽。

## 全局样式策略

修改 `frontend/src/index.css`，但不直接扩大全局组件覆盖范围。

- 保留现有颜色、圆角、边框和阴影变量。
- 将表格、Card、Modal 的密度样式限定在应用壳或页面组件类名下。
- 表格表头和单元格使用响应式 padding，不再全局固定为较大的 `16px 24px` 和 `20px 24px`。
- 对长文本按字段用途分别使用省略、正常换行或 `overflow-wrap: anywhere`。
- 所有 Flex 主要内容区域补充 `min-width: 0`。
- 只在表格容器使用 `overflow-x: auto`，页面根节点不使用全局横向滚动。

## 页面迁移设计

### 需求管理

修改 `frontend/src/pages/Requisitions/List.tsx`：

- 将搜索部门、状态筛选和操作按钮从 Card `extra` 移到 `ResponsiveToolbar`。
- 桌面横向排列，中屏换行，小屏输入控件占满宽度。
- 表格保留现有列、选择、分页和操作按钮。
- `scroll.x` 改为表格容器内部的自适应滚动，不让 1400px 宽度扩散到页面。
- 编辑/新增弹窗在小屏变成单列。

### 简历管理

修改 `frontend/src/pages/Resumes/List.tsx`：

- 顶部上传、导出、BOSS 导入、飞书导入、刷新和 AI 工具按主次分组。
- 统计卡片在桌面四列、中屏两列、小屏单列或两列。
- 状态、岗位、专业、学历、年龄、性别筛选使用自适应网格。
- 全选、批量入库、批量淘汰、批量删除、搜索和重置独立成操作区。
- 候选人卡片拆分为基础信息、岗位/状态标签、AI 评估区和操作区。
- 候选人姓名设置为不可压缩，岗位和标签允许换行，长标签显示省略和 Tooltip。
- 操作按钮在窄屏换到下一行；极窄屏只将低频操作收进更多菜单，所有动作仍可执行。
- AI 维度标签继续自动换行，评分数据和筛选行为不变。

### 简历详情

修改 `frontend/src/pages/Resumes/Detail.tsx`：

- 保留 PDF 预览和字段编辑功能。
- 桌面左右分栏，窄屏改为上下排列。
- AI 分析区域允许长文本换行，避免内容撑出页面。
- 详情操作区在窄屏换行，所有保存、取消和重新分析动作保持可见。

### 招聘日报和仪表盘

修改 `frontend/src/pages/DailyReports/List.tsx`、`frontend/src/pages/Dashboard/index.tsx` 及其组件：

- 统计卡片使用自适应网格。
- 报表表格在自身容器内横向滚动。
- 日报详情弹窗宽度跟随视口限制。
- 仪表盘继续复用现有断点，并统一页面外边距和卡片间距。

### 其他页面

按相同组件和 CSS 规则迁移岗位、面试、入职、试用期、人才库、岗位映射、面试官管理、用户、邮件、系统设置和工作流页面。迁移过程中只替换布局容器，不重写数据请求。

## 数据和功能不变约束

每次页面迁移必须确保以下行为前后相同：

- API URL、请求方法、参数和响应字段不变。
- 路由地址不变。
- 权限过滤和菜单显示不变。
- 分页、排序、筛选和筛选条件持久化不变。
- 简历选择、批量操作、上传、AI 评估和重新评估不变。
- 表格列不删除；只改变滚动和展示方式。
- 所有按钮仍然可点击，不能仅通过 `display: none` 隐藏业务动作。

## 测试和验收

### 自动测试

- 为响应式状态判断提取纯函数，并用 Vitest 覆盖桌面、紧凑、窄屏和极窄屏边界值。
- 保持现有前端 Vitest 全量测试通过。
- 保持 Worker 测试和前端构建通过。
- 对需要修改的页面补充不影响业务数据的渲染/布局回归检查。

### 视觉验收矩阵

检查以下尺寸和缩放组合：

| 视口 | 缩放 |
| --- | --- |
| 1920×1080 | 100%、125%、150%、175%、200% |
| 1440×900 | 100%、125%、150%、175%、200% |
| 1280×720 | 100%、125%、150% |
| 1024×768 | 100% |
| 768×1024 | 100% |
| 390×844 | 100% |

验收要求：页面没有横向滚动条；表格内部可以滚动；姓名、标题和按钮不溢出；弹窗不超过视口；菜单和所有核心操作可访问；桌面布局没有明显视觉退化。

## 发布策略

1. 从 `main` 创建响应式改造分支。
2. 先完成 Layout 和通用组件，在本地验证。
3. 再按需求管理、简历管理、简历详情、日报/仪表盘、其他页面分批提交。
4. 每批使用本地或 Cloudflare Preview 进行视觉验收。
5. 不执行数据库迁移，不修改生产配置。
6. 全量回归通过后合并 `main`，生产发布前再次确认。
7. 每批保留独立 Git 提交，线上问题可回滚到改造前提交。

## 预期交付物

- 响应式应用骨架和侧边栏/顶部栏行为。
- 通用页面标题、工具栏、表格和弹窗布局组件。
- 需求管理和简历管理的响应式迁移。
- 简历详情、招聘日报和仪表盘的响应式迁移。
- 其他业务页面的统一迁移。
- Vitest、构建和视觉验收记录。
- 不涉及后端或数据库变更的 Git 提交历史。
