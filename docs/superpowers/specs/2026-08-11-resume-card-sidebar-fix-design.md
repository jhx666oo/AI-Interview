# 简历卡片首行与侧边栏高度修复设计

日期：2026-08-11

## 背景

响应式改造上线后，简历管理卡片的首行信息在部分桌面宽度下容易被状态标签和操作区挤压，视觉上不再保持原来的横向排列；左侧导航仍依赖固定定位和主内容的 `margin-left`，长页面滚动时侧栏高度与页面内容的关系不稳定。

## 目标

1. 保持简历卡片首行原有顺序：复选框、候选人信息、岗位、AI 状态/硬条件、右侧操作按钮。
2. 能力维度评分继续独立占下一行，维度标签保持横向排列并仅在空间不足时换行，不改变数据、文案或交互。
3. 桌面与 compact 布局的侧栏由应用壳层撑满视口，并在长页面滚动时保持稳定；移动端抽屉行为不变。
4. 不修改 API、数据结构、权限、路由、业务动作或生产数据。

## 方案

### 简历卡片

将卡片首行拆为有语义的 `resume-card__header`、`resume-card__identity`、`resume-card__status` 和 `resume-card__actions` 容器。桌面模式使用 `flex-wrap: nowrap`，身份和状态区域允许收缩/省略，操作区保持不收缩；compact/mobile 模式允许首行在必要时换行。评分摘要和维度标签保留独立的 `resume-card__evaluation` 行，继续使用横向 `flex-wrap`。

### 应用侧栏

桌面与 compact 模式移除固定定位带来的主内容补偿关系，改为外层 Layout 的 flex 子项。侧栏设置 `position: sticky; top: 0; height: 100vh` 并让菜单区域独立纵向滚动，确保侧栏始终覆盖完整视口高度且不随长页面内容失去导航。移动端仍由 Drawer 渲染，不复用桌面侧栏定位规则。

## 验证

- 新增源码回归检查，锁定评分维度行仍是独立横向容器，侧栏使用 sticky/flex 壳层规则。
- 运行前端测试和构建、Worker 测试。
- 本地浏览器检查 `/resumes` 与其他关键页面在 1440、1024、768、390 宽度下无页面级横向溢出。
- 生产环境不在本分支验证阶段修改；上线需另行确认。
