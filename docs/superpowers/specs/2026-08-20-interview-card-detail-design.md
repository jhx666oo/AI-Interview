# 面试提醒候选人详情页设计

## 目标

在不改变现有飞书面试提醒链接格式的前提下，让 `/interview-card/:token` 展示候选人的完整招聘上下文：简历原件与解析字段、AI 评估、HR 备注、业务筛选、一面/二面评价和当前流程状态。

## 范围

- 保留现有面试提醒发送接口和 Token 有效期、撤销机制。
- 扩展面试卡片只读数据接口，统一从 D1 查询候选人和流程数据。
- 修复面试记录与简历记录的关联；无法唯一匹配时返回明确的人工处理状态，不按姓名静默猜测。
- 增加 PDF 预览/下载代理和空数据占位状态。
- 面向桌面和移动端优化详情页布局。
- 本次不增加公开写操作，不改变飞书卡片消息内容。

## 数据合同

接口继续使用 `GET /api/public/interview-card/:token`，保留现有字段并增加：

- `candidate.resume_file`: `available`、`preview_url`、`download_url`。
- `candidate.ai`: 总分、能力维度、初筛结论、优势、风险、建议问题和硬性条件结果。
- `candidate.hr`: 决策、备注、操作人和操作时间。
- `candidate.business_screening`: 状态、备注、操作人和操作时间。
- `candidate.current_status`: 后端确定的状态编码、展示名称、更新时间和来源。
- `interviews[]`: 各轮安排、面试官、会议/地点、评分、评价、结论和备注。
- `timeline[]`: 候选人阶段事件，按发生时间升序返回。

所有公共字段按 Token 只读权限返回；联系方式默认结构化脱敏，PDF 仍通过 Token 代理访问。接口使用 `Cache-Control: no-store`，不能通过搜索引擎索引。

## 状态规则

状态在 Worker 中统一计算，前端只渲染 `code` 和 `label`。优先级为：HR 淘汰 → 业务不通过 → 面试未通过 → 已入职/Offer → 当前面试阶段 → AI/HR/业务待处理 → 待定。缺少记录时展示“暂无记录”，不伪造通过或淘汰。

## 页面结构

- 顶部摘要：姓名、岗位、当前状态、最近一轮、面试时间、面试官和地点/会议链接。
- 左侧（桌面）或顶部（移动）：PDF 原件预览与下载。
- 候选人档案：结构化字段、工作经历、教育经历。
- AI 评估：总分、能力维度、结论、优势、风险、建议问题和硬性条件。
- HR 与业务筛选：分别展示决策、备注、操作人和时间。
- 面试情况：一面、二面按轮次展示安排、评分、评价、结论和分题备注。
- 流程时间线：显示阶段事件；无事件时显示“暂无流程记录”。

桌面使用两栏布局，窄屏改为单栏；长文本换行，面试轮次可折叠，当前轮次默认展开。

## 安全与兼容

- Token 过期、撤销、无效分别返回对应错误状态。
- PDF 不暴露底层对象存储地址，Worker 代理流式返回。
- 通过 `resume_id` 关联简历；旧数据没有 `resume_id` 时只允许唯一的姓名+岗位候选，否则返回未关联提示。
- 历史链接继续使用同一 Token；数据更新后刷新页面即可看到最新 D1 状态。

## 验证标准

- API 测试覆盖：有效 Token、过期 Token、关联简历、无简历、同名歧义、完整 AI/HR/业务/面试数据和 PDF 代理。
- 前端测试覆盖：所有分区渲染、空数据占位、状态标签、评价长文本换行和移动端布局契约。
- 生产构建、TypeScript 检查和现有 Worker/Frontend 测试通过。
