# 仪表盘 v3 数据口径

## 数据源与优先级

飞书多维表是岗位、事业部、HRBP 和岗位累计招聘指标的主数据源；D1 是 AI-Interview 的系统增量源。Worker 先按“岗位名称 + 城市”合并两边数据，再生成 KPI 和漏斗，浏览器不直接读取飞书。

“简历推送”指简历第一次进入 AI-Interview，来源包括本地上传、外部接口、邮件拉取和飞书同步。同一份简历用 `resume_ingest_key` 或文件 SHA-256 幂等，只计一次；重试、OCR 和 AI 重算不会改变接收时间。

## 统计集合

- P0-紧急、P1-正常且在招人数大于 0、招聘状态不是“已取消”的岗位进入 KPI、漏斗、事业部、HRBP 和 AI 诊断。
- P2-储备岗不进入上述统计，只进入 P2 储备岗明细。
- 平均完结周期使用独立集合：P0/P1、在招人数大于 0、状态含“完成”或“取消”、已耗时天数大于 0。已取消岗位可进入周期平均，但不进入数量汇总。
- 漏斗采用岗位累计值相加，不做候选人 DISTINCT。终面通过字段有值（包括数值 0）时使用 3 面通过，否则回退到 2 面通过。

## v3 漏斗

全局七级：简历推送 → 安排1面 → 1面通过 → 2面通过 → 终面通过 → 发放 Offer → 已入职。

事业部 mini 漏斗六级：简历推送 → 安排1面 → 1面通过 → 2面通过 → 发放 Offer → 已入职。

转化率分别为：终面通过 ÷ 安排1面、Offer ÷ 终面通过、入职 ÷ Offer。分母为 0 时返回 `null`，前端显示“—”。HRBP 效能链路为：1面 ÷ 简历、终面 ÷ 1面、Offer ÷ 终面、入职 ÷ Offer；颜色阈值为 ≥30% 绿色、≥15% 橙色、>0 红色、0 灰色。

## 兼容与安全

v3 接口为 `GET /api/dashboard/recruiting-board-v3`，快照在同一张 D1 表中以 `schema_version: dashboard-v3` 保存。旧 v2 接口、旧快照和旧分享链接保持原格式；公开分享只返回岗位聚合字段，不返回简历正文、候选人个人信息、D1 原始记录或内部 ID。
